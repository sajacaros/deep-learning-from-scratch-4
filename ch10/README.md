# CHAPTER 10 한 걸음 더
- 9장까지 강화 학습의 **기본기**를 밑바닥부터 만들었음

- 이 장은 구현 없이, 그 기본기가 **실제 연구와 응용에서 어떻게 확장되는지** 조망함
  - 10.1~10.3: 알고리즘 지도와 고급 알고리즘
  - 10.4: 사례 연구(바둑·로봇·NAS)

## 10.1 심층 강화 학습 알고리즘 분류
- ![](../images/figures/fig%2010-1.png)
  - 심층 강화 학습 알고리즘의 계보를 한 장으로 정리한 그림
  - **볼 곳**: 맨 위의 첫 갈래가 **모델 기반 / 모델 프리**라는 것
  |분류 |뜻 |이 책에서 |
  |:--|:--|:--|
  |**모델 기반**(model-based) |환경 모델(`p`, `r`)을 **알고 있거나 배움** |4장 동적 프로그래밍 |
  |**모델 프리**(model-free) |모델 없이 **경험만으로** 학습 |5장 이후 전부 |
  - 모델 기반은 다시 둘로 나뉨
    - **주어진 모델 이용** — 바둑처럼 규칙이 완전히 알려진 경우(알파고, 알파제로)
    - **모델 학습** — 환경 자체를 신경망으로 배운 뒤 그 안에서 상상으로 연습(World Models, MBVE)
  - 모델 프리도 둘로 나뉨
    - **가치 기반**(value-based) — 가치 함수를 배우고 탐욕화(DQN, Double DQN) → 6~8장
    - **정책 기반**(policy-based) — 정책을 직접 배움(정책 경사법, REINFORCE) → 9장
  - **볼 곳**: 두 상자 사이에 걸쳐 있는 **행위자-비평자** — 9.4에서 만든 그 위치
- 이 분류가 실전에서 갖는 의미
  |  |모델 기반 |모델 프리 |
  |:--|:--|:--|
  |샘플 효율 |좋음(모델 안에서 무한히 연습 가능) |나쁨(실제로 겪어야 함) |
  |모델 오차 |모델이 틀리면 통째로 무너짐 |해당 없음 |
  |적용 범위 |모델을 알거나 배울 수 있어야 |거의 모든 문제 |
  - 현실 문제에서 샘플을 얻는 비용이 크다면(로봇) 모델 기반이 매력적임
## 10.2 정책 경사법 계열의 고급 알고리즘
### 10.2.1 A3C, A2C
- 9장 행위자-비평자의 약점 — **한 개의 환경에서 순차적으로만** 경험을 모음
  - 연속한 경험이 서로 닮아 있음(8.2.1에서 본 그 문제)
  - DQN은 경험 재생으로 풀었지만, 행위자-비평자는 **온-정책**이라 옛 데이터를 쓸 수 없음
- ![](../images/figures/fig%2010-2.png)
  - **A3C**(Asynchronous Advantage Actor-Critic)
  - **볼 곳**: 환경-에이전트 쌍이 **여러 벌** 있고, 각자의 학습 결과(기울기)를 전역 신경망에 보냄
  - 여러 환경이 **동시에 서로 다른 곳을 겪으므로** 데이터의 상관관계가 자연히 끊김
  - 각 일꾼이 **비동기**로(다 기다리지 않고) 갱신하는 것이 이름의 첫 A
  - 경험 재생 없이도 학습이 안정되고, CPU 여러 개로 병렬화되어 빠름
- ![](../images/figures/fig%2010-3.png)
  - A3C의 신경망 구조 — 앞쪽 합성곱층을 **공유**하고 뒤에서 두 갈래로 나뉨
  - **볼 곳**: 위 갈래가 소프트맥스를 거쳐 정책 `π(a|s)`, 아래 갈래가 가치 `V_π(s)`
  - 9.4.2에서는 `PolicyNet`과 `ValueNet`을 완전히 따로 두었지만, 여기서는 특징 추출부를 공유
  - 화면에서 '무엇이 중요한가'를 읽는 일은 정책과 가치가 함께 쓸 수 있는 능력이기 때문
  - 8.4.3 Dueling DQN의 갈래 구조와 같은 발상
- ![](../images/figures/fig%2010-4.png)
  - **A2C**(Advantage Actor-Critic) — A3C에서 **비동기(A)를 뺀** 동기 버전
  - **볼 곳**: 여러 환경의 상태를 **하나의 배치로 묶어** 신경망에 한 번 넣고,
    나온 행동을 다시 각 환경에 나눠줌
  - 신경망이 하나뿐이라 GPU를 효율적으로 쓸 수 있음
  - 성능이 A3C와 비슷하거나 더 나은 것으로 밝혀져, 실무에서는 A2C를 더 많이 씀
    - '비동기'가 성능의 원인이 아니라 **병렬 환경**이 원인이었다는 뜻
### 10.2.2 DDPG
- 문제: **행동이 연속값**일 때 Q 러닝을 쓸 수 없음
  - `max_a Q(s,a)`를 계산하려면 모든 행동을 훑어야 하는데, 연속이면 무한히 많음
- ![](../images/figures/fig%2010-5.png)
  - 9.5에서 본 방식 — 신경망이 **정규분포의 평균**을 내고, 거기서 샘플링해 행동을 얻음
  - **볼 곳**: 신경망과 행동 사이에 **분포와 샘플링 단계**가 끼어 있음
  - 확률적 정책이라 탐색이 저절로 되지만, 샘플링 때문에 기울기 추정의 분산이 큼
- ![](../images/figures/fig%2010-6.png)
  - **DDPG**(Deep Deterministic Policy Gradient)의 정책 — 확률분포를 거치지 않고
    **행동값 자체를 결정적으로** 출력
  - **볼 곳**: 그림 10-5에 있던 분포와 샘플링이 **통째로 사라졌음**(`μ_θ(s)`가 곧 행동)
- ![](../images/figures/fig%2010-7.png)
  - 두 신경망의 연결 — 정책 `μ_θ(s)`가 낸 행동을 Q 신경망 `Q_φ(s,a)`에 그대로 넣음
  - **볼 곳**: `s → a → q`로 **한 줄로 이어진다**는 것
  - 그래서 `q`를 크게 만드는 방향의 기울기가 **Q 신경망을 거쳐 정책까지 흘러감**
  - `max_a`를 푸는 대신, **경사 상승법으로 좋은 행동을 찾아가는 것**
- 성격 정리
  - 결정적 정책이라 탐색이 안 됨 → 행동에 **잡음을 더해** 탐색
  - 오프-정책이라 **경험 재생을 쓸 수 있음**(9장 정책 경사법은 온-정책이라 불가능했음)
  - DQN의 목표 신경망도 그대로 가져다 씀
  - 로봇 제어처럼 행동이 연속인 문제의 표준 출발점(개선판으로 TD3, SAC가 있음)
### 10.2.3 TRPO, PPO
- 문제: 정책 경사법은 **한 걸음의 크기**에 매우 민감함
  - 학습률이 조금만 커도 정책이 크게 망가짐
  - 지도 학습과 달리 **정책이 망가지면 수집되는 데이터도 망가짐** → 회복이 어려움
- **TRPO**(Trust Region Policy Optimization)
  - '새 정책이 옛 정책에서 **너무 멀어지지 않도록**' 제약을 걸고 최적화
  - 거리는 확률분포 사이의 KL 발산으로 잼
  - 성능은 좋지만 제약 최적화를 풀어야 해서 구현이 복잡하고 계산이 무거움
- **PPO**(Proximal Policy Optimization)
  - 같은 아이디어를 **손실 함수를 자르는(clip) 것만으로** 구현
  - 확률비 `π_new/π_old`가 `[1-ε, 1+ε]`를 벗어나면 이득을 인정하지 않음
    - 5.5.2 중요도 샘플링의 그 비율이 여기서 '얼마나 멀어졌나'의 척도로 쓰임
  - 구현이 간단하고 성능이 좋아 **정책 경사법 계열의 사실상 표준**
  - 대규모 언어 모델의 RLHF에도 이 알고리즘이 쓰임
## 10.3 DQN 계열의 고급 알고리즘
### 10.3.1 범주형 DQN
- ![](../images/figures/fig%2010-9.png)
  - 지금까지 배운 `Q_π(s,a)`는 수익의 **기댓값** — 분포를 숫자 하나로 요약한 것
  - **볼 곳**: 왼쪽 분포 전체가 오른쪽 `1.8` 하나로 줄어듦. 이때 **모양 정보가 버려짐**
  - 평균은 같아도 '안정적으로 1.8'과 '반은 0, 반은 3.6'은 전혀 다른 상황
- **범주형 DQN**(Categorical DQN, C51) — 기댓값 대신 **수익의 분포 `Z_π(s,a)` 자체**를 학습
- ![](../images/figures/fig%2010-10.png)
  - 분포를 **막대 51개**(고정된 값 구간)의 확률로 근사
  - **볼 곳**: 주황 막대가 파란 실선(실제 분포)의 모양을 따라감
  - 신경망의 출력이 '행동마다 하나의 값'에서 '행동마다 51개의 확률'로 바뀜
  - 손실도 제곱 오차가 아니라 **분포 사이의 거리**로 바뀜
- 왜 더 잘 되는가 — 행동을 고를 때는 결국 기댓값만 쓰는데도 성능이 오름
  - 분포를 맞히는 일이 신경망에게 **더 풍부한 학습 신호**를 주기 때문으로 설명됨
  - 위험을 고려한 의사결정(최악의 경우를 피하기)으로도 확장할 수 있음
### 10.3.2 Noisy Network
- 문제: ε-탐욕 정책의 탐색은 **무작정 아무 행동이나** 하는 것
  - 몬테수마의 복수처럼 긴 탐험이 필요한 게임에서는 거의 통하지 않음
  - `ε`를 얼마로 둘지도 사람이 정해야 함(8.3.4의 어닐링 일정)
- **Noisy Network** — 신경망의 **가중치 자체에 학습 가능한 잡음**을 넣음
  - `W = μ + σ ⊙ ε`(`μ`, `σ`가 학습 대상, `ε`는 매번 새로 뽑는 잡음)
  - 잡음의 크기 `σ`도 학습되므로 **탐색의 양을 신경망이 스스로 조절**함
  - 확신이 선 상태에서는 `σ`가 작아지고, 모르는 상태에서는 크게 유지됨
  - 상태에 따라 탐색 정도가 달라진다는 점이 ε-탐욕과의 결정적 차이
### 10.3.3 레인보우
- ![](../images/figures/fig%2010-8.png)
  - DQN에서 갈라져 나온 개선안들과 그 이후의 흐름
  - **볼 곳**: 왼쪽 다섯 갈래(Double DQN, PER, Dueling DQN, 범주형 DQN, Noisy Network)가
    **레인보우 하나로 합쳐지고**, 그 뒤로 Ape-X → R2D2 → NGU → Agent57로 이어짐
  - **레인보우**(Rainbow, 2017)는 여기에 **다단계 학습**(n-step TD)까지 더한 6가지의 조합
    - 다단계 학습: TD법(1걸음)과 MC법(끝까지) 사이의 절충 — `n`걸음만 실제로 겪고 나머지는 추정
    - 6.1.2의 편향-분산 트레이드오프를 `n` 값으로 조절하는 것
- ![](../images/figures/fig%2010-11.png)
  - 레인보우와 각 구성 요소를 아타리에서 비교한 결과
  - **축**: x = 학습에 쓴 프레임 수(로그), y = 사람 대비 점수의 중앙값
  - **볼 곳**: 맨 위의 무지개색 선(레인보우)이 **모든 구간에서 다른 선들보다 위**
    - 회색(DQN)이 2억 프레임을 써서 도달한 점수(약 45%)를 **레인보우는 700만 프레임에** 달성
    - DQN이 끝내 도달하지 못한 100%(사람 수준)를 4,400만 프레임에서 넘김
  - 개별 개선안(주황 Distributional, 초록 Dueling, 파랑 Prioritized)도 각각 DQN보다 나음
  - **여러 개선안이 서로 방해하지 않고 더해진다**는 것이 이 논문의 발견
### 10.3.4 레인보우 이후의 발전된 알고리즘
- 그림 10-8의 오른쪽 흐름
  |알고리즘 |핵심 아이디어 |
  |:--|:--|
  |**Ape-X**(2018) |경험 수집을 수백 개 프로세스로 **분산**. 우선순위 버퍼를 공유 |
  |**R2D2**(2018) |신경망에 **LSTM**을 넣어 과거 기억을 다룸(부분 관측 문제 대응) |

## 10.4 사례 연구
### 10.4.1 보드 게임
- ![](../images/figures/fig%2010-12.png)
  - 오셀로의 **게임 트리** — 한 수를 둘 때마다 갈래가 퍼짐
  - **볼 곳**: 2장의 백업 다이어그램(그림 2-15)과 같은 모양
  - 바둑은 이 트리의 갈래가 `10^170`가지 — 전부 훑는 것은 불가능
- **알파고**(2016)
  - 사람의 기보로 정책 신경망을 **지도 학습**한 뒤, 자기 대국으로 강화 학습
  - **몬테카를로 트리 탐색**(MCTS)으로 유망한 가지만 골라 깊이 읽음
    - 1.3.3의 활용-탐색 문제를 트리 위에서 푸는 기법(UCB)
- **알파제로**(2017)
  - 사람의 기보를 **전혀 쓰지 않고** 백지에서 자기 대국만으로 학습
  - 정책과 가치를 **하나의 신경망**에서 두 갈래로 출력(그림 10-3과 같은 구조)
  - 바둑·체스·쇼기를 같은 알고리즘 하나로 정복
  - 규칙이 완전히 알려져 있으므로 **모델 기반**(그림 10-1의 '주어진 모델 이용')
- **MuZero**(2019) — 규칙조차 주지 않고 **환경 모델까지 학습**(그림 10-1의 '모델 학습')
### 10.4.2 로봇 제어
- 로봇에서 강화 학습이 어려운 이유
  - 시행착오에 **실제 시간과 마모**가 듦. 넘어지면 기계가 부서짐
  - 행동이 **연속값**(관절 토크) → DDPG·PPO 계열이 필요
- ![](../images/figures/fig%2010-13.png)
  - 로봇 팔 **일곱 대**를 동시에 돌려 경험을 모으는 모습
  - **볼 곳**: 같은 작업을 하는 팔이 나란히 놓여 있음 — 10.2.1 A3C/A2C의 병렬 환경을
    **물리적으로** 구현한 것
  - 데이터 수집 속도가 7배가 되고, 개체마다 조금씩 다른 조건이 일반화에도 도움이 됨
- ![](../images/figures/fig%2010-15.png)
  - 로봇 손으로 루빅스 큐브를 맞추는 실험(OpenAI)
  - **볼 곳**: 배경과 조명, 큐브 색이 사진마다 조금씩 다름
  - **Domain Randomization** — 시뮬레이터의 물리 계수·질감·조명을 **무작위로 흔들어가며** 학습
  - 그러면 에이전트는 '어떤 조건에서도 통하는' 정책을 배우게 되어,
    현실이 그 무작위 범위 안의 한 경우처럼 보이게 됨
  - 시뮬레이터와 현실의 간극(**sim-to-real gap**)을 넘는 대표적 처방
### 10.4.3 NAS
- **NAS**(Neural Architecture Search) — 신경망 구조 설계 자체를 강화 학습으로 자동화
- ![](../images/figures/fig%2010-14.png)
  - **볼 곳**: 1.1.3의 그림 1-3(에이전트-환경 상호작용)과 완전히 같은 구조
  |강화 학습의 요소 |NAS에서의 대응 |
  |:--|:--|
  |에이전트 |구조를 생성하는 RNN |
  |행동 |신경망 아키텍처를 하나 만들어냄 |
  |환경 |그 신경망을 데이터로 학습시켜 봄 |
  |보상 |검증 데이터에서의 인식 정확도 |
  - '문제를 MDP로 세울 수 있으면 강화 학습을 쓸 수 있다'는 것을 보여주는 사례
  - 다만 한 번의 보상을 얻는 데 신경망 하나를 통째로 학습시켜야 해서 **비용이 극단적으로 큼**
### 10.4.4 기타 예시
- **데이터 센터 냉각**(DeepMind) — 냉각 장치 제어를 강화 학습으로 최적화해 전력 40% 절감
- **칩 배치**(구글) — 반도체의 부품 배치를 강화 학습으로 설계. 사람보다 빠르고 좋은 배치를 찾음
- **추천 시스템** — 당장의 클릭이 아니라 **장기적인 사용자 만족**을 수익으로 두는 문제
- **금융 트레이딩**, **교통 신호 제어**, **재고 관리**
- 공통점 — 하나같이 **지금의 선택이 나중의 상황을 바꾸는** 문제
  - 그것이 2장에서 정의한 MDP의 조건
## 10.5 심층 강화 학습이 풀어야 할 숙제와 가능성
### 10.5.1 현실 세계에 적용하기
- 가장 큰 벽은 **샘플 효율**
  - Agent57은 아타리 한 게임에 수백억 프레임을 씀 — 사람은 몇 판이면 요령을 익힘
  - 현실에서 그만큼의 시행착오를 허용하는 문제는 거의 없음
- 대응 방향
  |방향 |내용 |
  |:--|:--|
  |**시뮬레이터** |가상에서 학습하고 현실로 옮김. 간극은 Domain Randomization으로 |
  |**모델 기반** |환경 모델을 배워 그 안에서 연습(그림 10-1의 왼쪽 가지) |
  |**오프라인 강화 학습** |이미 쌓인 로그 데이터만으로 학습 |
  |**모방 학습** |사람의 시범에서 출발해 시행착오를 줄임 |
- ![](../images/figures/fig%2010-16.png)
  - **왼쪽(일반적인 강화 학습)**: 에이전트와 환경 사이에 화살표가 **양방향**
  - **오른쪽(오프라인 강화 학습)**: 데이터셋에서 에이전트로 **한 방향뿐**
  - **볼 곳**: 오른쪽에는 환경이 아예 없음 — 학습 중에 새 행동을 시험해볼 수 없음
  - 의료·자율주행처럼 **탐색 자체가 위험한** 분야에서 필수적인 설정
  - 어려운 점: 데이터에 없는 행동의 가치를 신경망이 멋대로 부풀림(그런데 확인할 방법이 없음)
  - 5.5의 오프-정책이 극단으로 간 형태 — 행동 정책 `b`가 **과거에 고정되어 바꿀 수 없음**
### 10.5.2 MDP로 공식화하기 위한 팁
- 실무에서 강화 학습을 쓸 때 알고리즘보다 어려운 것이 **문제를 MDP로 세우는 일**
- **상태** — 마르코프 성질을 만족하도록 필요한 정보를 모두 담을 것(2.2.1)
  - 속도가 중요하면 위치만이 아니라 `(위치, 속도)`를 상태로
  - 화면 한 장으로 부족하면 4프레임을 겹칠 것(8.3.2)
  - 그래도 부족하면 LSTM 같은 기억 장치를 쓸 것(R2D2)
- **보상** — 강화 학습에서 가장 위험한 설계 지점
  - 에이전트는 **보상을 최대화할 뿐, 우리의 의도를 따르지 않음**
  - 잘못 설계하면 의도하지 않은 편법(**보상 해킹**)을 찾아냄
    - 예) 레이싱 게임에서 완주 대신 점수 아이템만 뱅글뱅글 돌며 먹기
  - 성긴 보상(목표 달성에만 `+1`)은 학습이 어렵고, 촘촘한 보상은 편법을 부르기 쉬움
    - 그 사이의 균형을 잡는 것이 **보상 설계**(reward shaping)
  - 되도록 **정말 원하는 결과 그 자체**를 보상으로 두고, 나머지는 알고리즘에 맡길 것
- **행동** — 이산인지 연속인지에 따라 쓸 수 있는 알고리즘이 갈림(9.5)
- **할인율 `γ`** — 사실상 '몇 걸음 앞까지 볼 것인가'를 정하는 값(2.3.2)
### 10.5.3 범용 인공지능 시스템
- 강화 학습이 특별히 주목받는 이유 — **목표를 주기만 하면 방법은 스스로 찾는** 틀이기 때문
  - 지도 학습은 정답을 일일이 알려줘야 하지만, 강화 학습은 '무엇이 좋은가'만 알려주면 됨
  - 알파제로가 사람의 기보 없이 사람을 넘어선 것이 그 상징
- 'Reward is enough' 가설 — 보상 최대화라는 하나의 원리만으로 지능의 여러 능력이
  자연히 나타날 수 있다는 주장(Silver et al., 2021). 물론 논쟁 중인 가설
- 최근의 확장
  - **RLHF** — 사람의 선호를 보상 모델로 배우고, 그것으로 언어 모델을 PPO로 미세 조정
    - 보상을 사람이 설계하는 대신 **사람의 판단에서 배우는** 방향
    - 10.5.2의 '보상 설계가 어렵다'는 문제에 대한 현실적인 답 중 하나
  - 정답이 명확한 영역(수학·코드)에서는 **채점 결과를 그대로 보상으로** 쓰기도 함
- 남아 있는 근본 문제들
  - 샘플 효율, 안전성(탐색 중의 위험), 일반화(새 과제로의 전이), 보상 설계
## 10.6 정리
- 심층 강화 학습은 **모델 기반 / 모델 프리**로 크게 나뉘고,
  모델 프리는 다시 **가치 기반 / 정책 기반**으로 나뉨. 그 교집합이 **행위자-비평자**
- **정책 경사법 계열의 발전**
  |알고리즘 |해결한 문제 |
  |:--|:--|
  |A3C / A2C |병렬 환경으로 데이터 상관관계를 끊음(온-정책이라 경험 재생을 못 쓰므로) |
  |DDPG |행동이 연속일 때 `max_a`를 경사 상승으로 대체 |
  |TRPO / PPO |갱신 폭을 제한해 정책이 망가지는 것을 방지 |
- **DQN 계열의 발전**
  - 범주형 DQN(기댓값 대신 **수익의 분포**), Noisy Network(**학습되는 탐색**)
  - **레인보우** = Double + PER + Dueling + 범주형 + Noisy + 다단계
    - 개선안들이 서로 방해하지 않고 더해짐. DQN의 2억 프레임 성적을 700만 프레임에 달성
  - 이후 Ape-X(분산) → R2D2(기억) → NGU(탐험) → Agent57(아타리 57종 정복)
- **사례** — 알파고/알파제로(모델 기반 + MCTS), 로봇 제어(병렬 수집 + Domain Randomization),
  NAS(구조 설계를 MDP로), 데이터 센터 냉각·칩 배치·추천 시스템
- **남은 숙제** — 샘플 효율, 안전성, 보상 설계, 일반화
  - 오프라인 강화 학습·모델 기반·모방 학습이 그 대응 방향
  - 실무에서 가장 어려운 일은 알고리즘 선택이 아니라 **문제를 MDP로 세우는 것**
    - 상태에 필요한 정보를 다 담을 것(마르코프 성질), 보상은 정말 원하는 결과로 둘 것
- 이 책을 통해 만든 것들
  |장 |만든 것 |
  |:--|:--|
  |1 |밴디트 — 활용과 탐색, 증분 평균, ε-탐욕, 고정값 `α` |
  |2 |MDP — 상태·행동·전이·보상·정책, 수익과 가치 함수 |
  |3 |벨만 방정식과 벨만 최적 방정식, Q 함수 |
  |4 |동적 프로그래밍 — 정책 반복법, 가치 반복법 |
  |5 |몬테카를로법 — 모델 없이 경험으로, 오프-정책과 중요도 샘플링 |
  |6 |TD법 — SARSA, **Q 러닝** |
  |7 |신경망으로 `Q` 근사 |
  |8 |**DQN** — 경험 재생, 목표 신경망 |
  |9 |**정책 경사법** — REINFORCE, 베이스라인, 행위자-비평자 |
  - 이 장에 나온 고급 알고리즘들은 모두 이 표의 어딘가에 뿌리를 두고 있음
    - PPO의 확률비는 5장 중요도 샘플링, PER의 보정도 5장, Dueling의 `A = Q - V`는 3장,
      레인보우의 다단계 학습은 5장과 6장 사이의 절충
  - 새 논문을 읽을 때 **여기까지 되짚어 읽는 것**이 이 책이 남기는 가장 실용적인 습관
