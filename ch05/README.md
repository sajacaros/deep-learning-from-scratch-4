# CHAPTER 5 몬테카를로법
- 4장의 동적 프로그래밍은 **환경 모델(`p`, `r`)을 완전히 안다**는 전제에 기대고 있었음
  - 코드에서 `env.next_state()`와 `env.reward()`를 직접 불렀다는 점이 그 증거
- 현실에서는 그 전제가 거의 성립하지 않음
  - 바둑·로봇·게임 — 규칙은 알아도 모든 전이 확률을 표로 적어둘 수는 없음
- 이 장의 방법은 정반대 — **모델을 모른 채, 직접 해보고 그 결과의 평균**으로 가치를 추정
  - 이런 방식을 **몬테카를로법**(Monte Carlo method), 줄여서 **MC법**이라고 함
- 대신 조건이 하나 붙음: **에피소드가 끝나야** 수익을 알 수 있으므로 **일회성 과제**에만 쓸 수 있음
## 5.1 몬테카를로법 기초
### 5.1.1 주사위 눈의 합
- 주사위 두 개를 던져 나온 눈의 **합**의 기댓값을 구하는 문제로 시작
- ![](../images/figures/fig%205-1.png)
  - 두 번 던지는 과정을 전개한 그림 — 첫 번째 주사위 6갈래, 각각 다시 6갈래
  - **볼 곳**: 잎이 `36`개. 주사위가 셋이면 `216`개, `n`개면 `6^n`개로 폭발
- ![](../images/figures/fig%205-2.png)
  - 그 36가지를 합계별로 세어 만든 확률분포 — `7`이 `6/36`으로 가장 많음
  - 기댓값은 `Σ x p(x) = 7`
- 이렇게 **분포를 알고 계산하는 것**이 4장까지의 방식(동적 프로그래밍)
  - 문제는 `6^n`처럼 경우의 수가 폭발하거나, 애초에 분포를 모를 때
### 5.1.2 분포 모델과 샘플 모델
- ![](../images/figures/fig%205-3.png)
  - **볼 곳**: 왼쪽은 **표**를 내놓고, 오른쪽은 **주사위를 굴린 결과**를 내놓음
  |  |분포 모델(distribution model) |샘플 모델(sample model) |
  |:--|:--|:--|
  |가진 것 |확률분포 전체 |샘플을 만드는 능력만 |
  |예 |`p(s'\|s,a)` 표 |게임 시뮬레이터, 실제 로봇 |
  |쓰는 방법 |4장 동적 프로그래밍 |5장 몬테카를로법 |
  - 샘플 모델이 **훨씬 만들기 쉬움** — 주사위 굴리는 함수는 세 줄이면 되지만,
    합의 분포표를 만들려면 36가지를 다 세어야 함
- 몬테카를로법은 샘플 모델만 있으면 됨 — **여러 번 해보고 평균**
- 표본 평균이 참값으로 다가간다는 근거가 **큰 수의 법칙**
  - 1장에서 슬롯머신의 승률을 추정하던 것과 정확히 같은 논리
### 5.1.3 몬테카를로법 구현
- ![](../images/figures/fig%205-4.png)
  - 1.3.2에서 본 두 가지 평균 계산법 — 매번 전부 더하는 방식과 **증분 방식**
  - `V_n = V_{n-1} + (1/n)(s_n - V_{n-1})`
  - **볼 곳**: 아래 식에는 `s_1 ... s_{n-1}`이 등장하지 않음 → 샘플을 저장할 필요가 없음
- 예제 코드: [`s01_dice.py`](s01_dice.py)
```python
def sample(dices=2):
    x = 0
    for _ in range(dices):
        x += np.random.choice([1, 2, 3, 4, 5, 6])
    return x


trial = 1000
V, n = 0, 0
for _ in range(trial):
    s = sample()
    n += 1
    V += (s - V) / n     # 증분 방식
    print(V)
```
- 1,000번 시행한 뒤의 값(실행할 때마다 달라짐)
  ```
  ...
  6.914914914914918
  6.916000000000003
  ```
  - **볼 곳**: 참값 `7`에 가깝지만 정확히 `7`은 아님 — 표본 평균이라 **오차가 남음**
  - 시행 횟수를 늘리면 줄어들지만 `1/√n`으로 느리게 줄어듦
- 몬테카를로법의 성격 정리
  - **장점**: 분포를 몰라도 됨, 경우의 수가 폭발해도 상관없음
  - **단점**: 값이 근사치이고 **매번 달라짐**. 정확도를 높이려면 시행을 크게 늘려야 함
## 5.2 몬테카를로법으로 정책 평가하기
### 5.2.1 가치 함수를 몬테카를로법으로 구하기
- ![](../images/equations/e%205-1.png)
  - 상태 가치 함수의 정의 `v_π(s) = E_π[G | s]`([식 5.1]) — 이것도 **기댓값**
  - 그렇다면 주사위와 똑같이 **표본 평균**으로 추정할 수 있음
- ![](../images/figures/fig%205-5.png)
  - 에이전트가 `s`에서 출발해 정책 `π`대로 움직여 목표(`□`)에 도달한 한 판
  - **볼 곳**: 화살표 옆의 숫자가 **확률이 아니라 실제로 받은 보상**
  - 백업 다이어그램과 모양은 같지만 의미가 다름 — 갈래가 없는 **한 줄기의 경험**
  - 이 경험 하나에서 수익 하나를 얻음: `G^(1) = 1 + γ·0 + γ²·2`
- ![](../images/figures/fig%205-6.png)
  - 같은 정책으로 한 판 더. 길이도 보상도 다름 → `G^(2) = 0 + γ·0 + γ²·1 + γ³·1`
  - **볼 곳**: 두 시도의 **길이가 다르다는 것**. 환경이나 정책이 확률적이라 매번 달라짐
- ![](../images/equations/e%205-2.png)
  - 이렇게 얻은 수익들의 평균이 가치의 추정치([식 5.2])
  - `V_π(s) = (G^(1) + G^(2) + ... + G^(n)) / n`
- 여기서 **환경 모델이 전혀 쓰이지 않았다는 점**이 중요
  - 필요한 것은 '행동을 넣으면 보상과 다음 상태를 돌려주는' 샘플 모델뿐
### 5.2.2 모든 상태의 가치 함수 구하기
- 문제: 위 방법은 **한 상태 `s`의 가치**만 구함. 우리가 원하는 것은 모든 상태
- ![](../images/figures/fig%205-7.png)
  - 곧이곧대로 하면 — `A`에서 시작하는 판을 여러 번, `B`에서 시작하는 판을 여러 번, `C`도...
  - **볼 곳**: 세로 구분선으로 나뉜 **세 덩어리**. 상태마다 실험을 따로 돌리고 있음
  - 상태가 12개면 실험이 12세트, 100개면 100세트 → 낭비가 큼
  - 게다가 현실에서는 **원하는 상태에서 시작하는 것 자체가 불가능**한 경우가 많음
    (로봇을 임의의 자세로 옮겨놓고 시작할 수는 없음)
### 5.2.3 몬테카를로법 계산 효율 개선
- 아이디어: 한 판의 경험 안에는 **거쳐 간 모든 상태의 정보**가 들어 있음
- ![](../images/figures/fig%205-8.png)
  - `A → B → C → 종료`로 진행하며 보상 `R_0`, `R_1`, `R_2`를 받은 한 판
  - `A`의 수익: `G_A = R_0 + γR_1 + γ²R_2`
- ![](../images/figures/fig%205-9.png)
  - **볼 곳**: 점선 상자 안쪽만 떼어내면 그대로 **`B`에서 시작한 한 판**이 됨
  - `G_B = R_1 + γR_2` — 새로 실험할 필요 없이 같은 경험에서 뽑아 쓸 수 있음
  - 마찬가지로 `G_C = R_2`
- 게다가 이 셋은 **뒤에서부터 계산하면 재사용**됨
  ```
  G_C = R_2
  G_B = R_1 + γ·G_C
  G_A = R_0 + γ·G_B
  ```
  - 3장의 재귀 구조 `G_t = R_t + γG_{t+1}`을 그대로 쓴 것
  - 앞에서부터 계산하면 상태마다 뒤쪽 보상을 다시 훑어야 해서 `O(T²)`,
    뒤에서부터 계산하면 `O(T)`
- 이것이 코드에서 `reversed(self.memory)`로 나타남 — 5.3.2에서 확인
## 5.3 몬테카를로법 구현
### 5.3.1 step() 메서드
- ![](../images/figures/fig%205-10.png)
  - 대상은 4장과 같은 3×4 그리드 월드. 다만 이번에는 **모델을 쓰지 않고 직접 걸어봄**
- ![](../images/figures/fig%205-11.png)
  - 코드의 변수 이름과 수식 기호의 대응
  - **볼 곳**: `next_state`가 다음 걸음의 `state`가 된다는 것(그림의 점선 부분)
  - `env.step(action)`은 `(next_state, reward, done)`을 돌려줌
    |코드 |수식 |
    |:--|:--|
    |`state` |`S_t` |
    |`action` |`A_t` |
    |`reward` |`R_t` |
    |`next_state` |`S_{t+1}` |
  - 4장에서 쓰던 `env.next_state(s, a)`·`env.reward(...)`와 달리, `step()`은
    **에이전트가 지금 있는 자리에서 한 걸음**만 나아가게 함 → 모델을 들여다볼 수 없음
### 5.3.2 에이전트 클래스 구현
- 예제 코드: [`s02_mc_eval.py`](s02_mc_eval.py) — 무작위 정책을 MC법으로 평가
```python
class RandomAgent:
    def __init__(self):
        self.gamma = 0.9
        self.pi = defaultdict(lambda: {0: 0.25, 1: 0.25, 2: 0.25, 3: 0.25})
        self.V = defaultdict(lambda: 0)
        self.cnts = defaultdict(lambda: 0)   # 상태별 방문 횟수 (증분 평균의 n)
        self.memory = []                     # 한 에피소드의 경험

    def add(self, state, action, reward):
        self.memory.append((state, action, reward))

    def eval(self):
        G = 0
        for data in reversed(self.memory):   # 뒤에서부터 따라가기
            state, action, reward = data
            G = self.gamma * G + reward      # G_t = R_t + γG_{t+1}
            self.cnts[state] += 1
            self.V[state] += (G - self.V[state]) / self.cnts[state]   # 증분 평균
```
- 세 줄에 이 장의 요점이 다 들어 있음
  - `reversed(...)` — 5.2.3의 뒤에서부터 계산하기
  - `G = γ*G + reward` — 재귀 구조를 그대로 옮긴 한 줄
  - `V[state] += (G - V[state]) / cnts[state]` — 1.3.2의 증분 평균과 완전히 같은 식
- 실행 루프는 '한 판 끝날 때까지 걷고, 끝나면 평가'
```python
for episode in range(episodes):
    state = env.reset()
    agent.reset()
    while True:
        action = agent.get_action(state)
        next_state, reward, done = env.step(action)
        agent.add(state, action, reward)
        if done:              # 목표에 도달해야
            agent.eval()      # 비로소 수익을 알 수 있음
            break
        state = next_state
```
- **에피소드가 끝나야 갱신한다**는 점이 MC법의 특징이자 한계 — 6장 TD법이 바로 이 점을 고침

## 5.4 몬테카를로법으로 정책 제어하기
- 지금까지는 **평가**만 했음. 이제 4장처럼 **개선**을 붙여 최적 정책을 찾음
### 5.4.1 평가와 개선
- ![](../images/equations/e%205-3%20&%205-4.png)
  - 탐욕화의 두 가지 형태([식 5.3], [식 5.4])
  - `μ(s) = argmax_a Q(s,a)` — `Q`를 쓰는 쪽
  - `μ(s) = argmax_a Σ_{s'} p(s'|s,a){ r + γV(s') }` — `V`를 쓰는 쪽
  - **볼 곳**: 아래 식에는 `p`와 `r`이 등장 → **모델이 필요**함
  - 모델을 모르는 이 장에서는 위 식밖에 쓸 수 없음 → **`V`가 아니라 `Q`를 추정해야 함**
    (3.3.1에서 예고한 'Q의 장점'이 여기서 결정적으로 작용)
- ![](../images/equations/e%205-5.png)
  - 그래서 평가 대상도 `Q`로 바꿈([식 5.5])
  - `Q_n(s,a) = Q_{n-1}(s,a) + (1/n){ G^(n) - Q_{n-1}(s,a) }`
  - 저장 단위가 상태 `s`에서 **(상태, 행동) 쌍**으로 바뀌었을 뿐 계산은 같음
- 절차는 4장 정책 반복법과 같음 — **평가(MC법) ↔ 개선(탐욕화)** 를 반복
### 5.4.2 몬테카를로법으로 정책 제어 구현
- 곧이곧대로 구현하면 문제가 생김 — **탐욕 정책은 탐색을 하지 않음**
- ![](../images/figures/fig%205-14.png)
  - 어떤 탐욕 정책과, 그 정책으로 시작 상태에서 걸었을 때 지나는 칸(하늘색)
  - **볼 곳**: 하늘색이 아닌 칸이 **절반**. 이 칸들은 영원히 방문되지 않음
  - 방문하지 않으면 `Q`가 갱신되지 않고, 갱신되지 않으니 정책도 바뀌지 않음
  - 처음에 우연히 나쁜 길을 골랐다면 **그 길에 영영 갇힘**
- 1장에서 본 그 문제 — **활용과 탐색의 상충**. 해법도 그때와 같음
### 5.4.3 ε-탐욕 정책으로 변경(첫 번째 개선 사항)
- ![](../images/figures/fig%205-15.png)
  - ε-탐욕 정책이 각 행동에 주는 확률
  - **볼 곳**: 막대 네 개가 **모두 `ε/4` 이상임**. 최선의 행동(`1`)만 거기서 `1-ε`만큼 더 높음
  - 확률이 `0`인 행동이 없음 → 모든 (상태, 행동)이 언젠가는 시도됨
- 구현
```python
def greedy_probs(Q, state, epsilon=0, action_size=4):
    qs = [Q[(state, action)] for action in range(action_size)]
    max_action = np.argmax(qs)

    base_prob = epsilon / action_size
    action_probs = {action: base_prob for action in range(action_size)}
    action_probs[max_action] += (1 - epsilon)
    return action_probs
```
  - `epsilon=0`을 넘기면 순수 탐욕 정책이 됨 — 5.5절에서 이 성질을 씀
  - 공용 구현은 [`../common/utils.py`](../common/utils.py)에 있음(동점일 때 무작위로 고르는 `argmax` 사용)
### 5.4.4 고정값 α 방식으로 수행(두 번째 개선 사항)
- 두 번째 문제: 정책이 계속 바뀌는데 `1/n` 평균은 **옛 정책의 성적까지 똑같은 비중**으로 셈함
  - `G^(1)`은 초기의 형편없는 정책이 낸 수익인데, 1,000번째 수익과 발언권이 같음
  - 1.5절의 **비정상 문제**와 같은 구조 — 대상이 변하는데 평균이 과거를 놓지 않음
- ![](../images/figures/fig%205-16.png)
  - **왼쪽(`1/n` 방식)**: 막대 높이가 전부 같음 — 오래된 수익도 그대로 반영
  - **오른쪽(고정값 `α` 방식)**: 오른쪽으로 갈수록 높아짐 — 최근 수익에 비중이 몰림
  - **볼 곳**: 1장 그림 1-18·1-19와 완전히 같은 한 쌍. 같은 처방을 다시 쓰는 것
- 갱신식을 `Q(s,a) ← Q(s,a) + α{ G - Q(s,a) }`로 바꿈(지수 이동 평균)
  - 방문 횟수 `cnts`가 필요 없어져 코드도 짧아짐
### 5.4.5 몬테카를로법으로 정책 반복법 구현(개선 버전)
- 예제 코드: [`s03_mc_control.py`](s03_mc_control.py) (`ε=0.1`, `α=0.1`, 10,000 에피소드)
```python
def update(self):
    G = 0
    for data in reversed(self.memory):
        state, action, reward = data
        G = self.gamma * G + reward
        key = (state, action)
        self.Q[key] += (G - self.Q[key]) * self.alpha              # 평가 (고정값 α)
        self.pi[state] = greedy_probs(self.Q, state, self.epsilon)  # 개선 (ε-탐욕)
```
- **볼 곳**: 평가와 개선이 **한 상태씩 번갈아** 일어남
  - 4.5.1 그림 4-21에서 본 그 구조 — 평가를 끝까지 돌리지 않고 곧바로 개선
  - 정책 반복법과 가치 반복법 사이 어딘가에 있는 형태(일반화된 정책 반복)
- ![](../images/figures/fig%205-17.png)
  - 학습된 `Q` 함수 — 칸마다 네 방향의 값을 삼각형으로 나눠 표시
  - **볼 곳**: 목표 왼쪽 칸의 오른쪽 삼각형이 `1.00` — 한 걸음이면 사과이므로 당연
  - 폭탄 칸 주변에 **음수(분홍)** 가 몰려 있음. 폭탄으로 향하는 행동만 골라 나쁘게 평가됨
  - 오른쪽 아래 두 칸의 값이 `0.00`인 것은 **거의 방문하지 않아** 초깃값 그대로인 것
- ![](../images/figures/fig%205-18.png)
  - 그 `Q`를 탐욕화한 정책 — 4장 그림 4-25(최적 정책)와 아래 줄 두 칸만 다름
  - **볼 곳**: 왼쪽 아래 칸이 `↑`(4장은 `→`) — 이쪽은 **동점이라 어느 쪽이든 최적**
    - `(2,0)`에서 `UP`과 `RIGHT`가 둘 다 `0.6561`
  - 그 오른쪽 칸은 `←`(4장은 `→`) — 이쪽은 **실제로 틀린 선택**
    - `(2,1)`의 참값은 `RIGHT` `0.7290`, `LEFT` `0.5905`로 차이가 뚜렷함
    - 목표에서 먼 칸이라 방문이 적어 `Q`가 덜 여문 것. 아래 시드별 비교와 같은 현상
- 다만 결과가 **실행할 때마다 다름**. 5개 시드로 돌려 4장의 최적 정책과 비교해보면
  ```
  on-policy (s03)  최적 행동 일치: 8/10, 9/10, 9/10, 6/10, 8/10
                   max|maxQ - v*|: 0.40, 0.30, 0.06, 0.73, 0.20
  ```
  - **볼 곳**: 10칸 중 1~4칸이 어긋남. 어긋나는 곳은 대개 **방문 횟수가 적은 칸**
  - DP는 12칸을 빠짐없이 훑어 정확한 답을 냈지만, MC법은 **가본 만큼만** 배움
  - 그래도 시작 지점에서 목표까지 가는 주 경로는 매번 제대로 찾아냄
## 5.5 오프-정책과 중요도 샘플링
### 5.5.1 온-정책과 오프-정책
- 5.4의 방식에는 어정쩡한 구석이 있음 — **평가하는 정책과 행동하는 정책이 같음**
  - 우리가 원하는 것은 최적(탐욕) 정책인데, 실제로 평가되는 것은 `ε`만큼 헤매는 정책
  - `ε`를 키우면 탐색은 잘 되지만 평가 대상이 목표에서 멀어지고, 줄이면 그 반대
  |  |설명 |이 장의 예 |
  |:--|:--|:--|
  |**온-정책**(on-policy) |평가·개선 대상과 행동하는 정책이 **같음** |[`s03_mc_control.py`](s03_mc_control.py) |
  |**오프-정책**(off-policy) |둘이 **다름** |[`s05_mc_control_offpolicy.py`](s05_mc_control_offpolicy.py) |
- 오프-정책에서는 두 정책에 이름을 붙임
  - **대상 정책**(target policy) `π` — 우리가 키우고 싶은 정책. 여기서는 순수 탐욕 정책
  - **행동 정책**(behavior policy) `b` — 실제로 움직이며 데이터를 모으는 정책. ε-탐욕 정책
- 이 분리의 이점
  - 탐색은 `b`가 마음껏 하고, 평가는 `π`에 대해 함 → 위의 상충이 풀림
  - 남이 만든 데이터, 옛날 데이터로도 학습할 수 있음(8장 경험 재생의 근거)
- 문제는 **`b`로 모은 데이터로 `π`의 기댓값을 어떻게 구하느냐**
### 5.5.2 중요도 샘플링
- ![](../images/figures/fig%205-19.png)
  - 확률분포 두 개 — `π`는 `3`에 몰려 있고(`0.8`), `b`는 고른 분포(`1/3`씩)
  - **볼 곳**: 같은 값 `3`을 두 분포가 **다른 확률**로 내놓는다는 것
- ![](../images/equations/e%205-6.png)
  - 기댓값 식에 `b(x)/b(x)`를 곱해 넣는 것이 전부([식 5.6])
  - `E_π[x] = Σ x π(x) = Σ x (π(x)/b(x)) b(x)`
- ![](../images/equations/e%205-7.png)
  - 정리하면 **`b`에 대한 기댓값**으로 바뀜([식 5.7])
  - `E_π[x] = E_b[ x · π(x)/b(x) ]`
  - 즉 `b`로 샘플링하되 **가중치 `ρ = π(x)/b(x)`를 곱해** 평균내면 `π`의 기댓값이 나옴
  - 이 가중치를 **중요도 가중치**(importance weight), 이 기법을 **중요도 샘플링**이라고 함
- ![](../images/figures/fig%205-21.png)
  - `b`에서 `3`이 뽑혔을 때의 가중치 `ρ = 0.8 / (1/3) = 2.4`
  - **볼 곳**: `π`에서 더 자주 나올 값이므로 **2.4배로 부풀려** 셈함
  - 반대로 `π`에서 드문 값(`1`, `2`)은 `0.1/(1/3) = 0.3`배로 깎임
- 예제 코드: [`s04_importance_sampling.py`](s04_importance_sampling.py) — `x=[1,2,3]`, `π=[0.1,0.1,0.8]`
```python
b = np.array([0.2, 0.2, 0.6])
samples = []
for _ in range(n):
    i = np.random.choice(np.arange(len(b)), p=b)   # b로 샘플링
    rho = pi[i] / b[i]                             # 가중치
    samples.append(rho * x[i])                     # 가중치를 곱해 저장
```
- **전제 조건**: `π(x) > 0`인 모든 `x`에서 `b(x) > 0`이어야 함
  - `b`가 절대 뽑지 않는 값이 있으면 그 부분은 영영 학습되지 않음(0으로 나누는 문제도 생김)
  - ε-탐욕 정책을 `b`로 쓰는 이유가 여기 있음 — 모든 행동에 `ε/4` 이상의 확률이 보장됨
### 5.5.3 분산을 작게 하기
- 중요도 샘플링은 **평균은 맞지만 분산이 커질 수 있음**
- ![](../images/figures/fig%205-20.png)
  - 과녁에 찍힌 점들 — 왼쪽은 흩어져 있고 오른쪽은 몰려 있음
  - **볼 곳**: 두 그림 모두 **중심(평균)은 같음**. 다른 것은 퍼진 정도뿐
  - 분산이 크면 같은 개수의 샘플로 얻는 추정치의 신뢰도가 낮음
- 실행 결과 — `b = [0.2, 0.2, 0.6]`으로 100개 샘플(참값 `2.7`)
  ```
  참값(E_pi[x]): 2.7
  몬테카를로법: 2.67 (분산: 0.46)
  중요도 샘플링: 2.64 (분산: 2.69)
  ```
  - **볼 곳**: 두 방법 모두 `2.7` 근처를 맞히지만 **분산이 6배 가까이 차이 남**
  - 가중치 `ρ`가 곱해지면서 값의 폭이 커지기 때문(`0.5×1`부터 `1.33×3`까지)
  - `b`를 균등분포 `[1/3, 1/3, 1/3]`로 더 멀어지게 하면 분산이 더 커짐
- **분산을 줄이는 방법은 `b`를 `π`에 가깝게 두는 것**
  - 극단적으로 `b = π`면 `ρ = 1`이라 분산이 원래대로 돌아옴(대신 오프-정책의 의미가 없어짐)
  - 실무에서는 탐색이 가능한 선에서 `b`를 최대한 `π`에 붙임(작은 `ε`)
- 오프-정책 MC 제어 구현: [`s05_mc_control_offpolicy.py`](s05_mc_control_offpolicy.py)
```python
def update(self):
    G = 0
    rho = 1
    for data in reversed(self.memory):
        state, action, reward = data
        key = (state, action)

        G = self.gamma * rho * G + reward           # 가중치를 수익에 반영
        self.Q[key] += (G - self.Q[key]) * self.alpha
        rho *= self.pi[state][action] / self.b[state][action]   # 가중치 누적

        self.pi[state] = greedy_probs(self.Q, state, epsilon=0)      # 대상 정책: 탐욕
        self.b[state] = greedy_probs(self.Q, state, self.epsilon)    # 행동 정책: ε-탐욕
```
- **볼 곳**: `rho`가 `*=`로 **곱해 쌓인다**는 것
  - 한 걸음의 가중치는 `π(a|s)/b(a|s)`지만, 여러 걸음의 수익에는 그 **곱**이 필요
  - 걸음 수가 길어질수록 `ρ`가 `0`에 가까워지거나 폭발함 → MC법 오프-정책의 고질적 약점
  - 6장 TD법이 한 걸음씩 갱신하는 덕에 이 곱이 짧아지는 것도 큰 장점
- 두 방식을 5개 시드로 비교해본 결과(4장 최적 정책 기준, 10,000 에피소드)
  ```
  on-policy (s03)  최적 행동 일치: 8/10, 9/10, 9/10, 6/10, 8/10
                   max|maxQ - v*|: 0.40, 0.30, 0.06, 0.73, 0.20
  off-policy(s05)  최적 행동 일치: 10/10, 7/10, 9/10, 10/10, 8/10
                   max|maxQ - v*|: 0.52, 0.70, 0.44, 0.73, 0.51
  ```
  - **볼 곳**: 아래쪽 `max|maxQ - v*|`가 오프-정책에서 **일관되게 더 큼**
  - 정책(행동의 순위)은 비슷하게 맞히지만 **값 자체의 추정은 더 부정확**
  - 5.5.3의 분산 이야기가 실제로 나타난 것 — `ρ`의 누적곱이 추정치를 흔듦
  - 온·오프 어느 쪽도 4장 DP의 정확도에는 못 미침. 모델을 포기한 대가
## 5.6 정리
- **몬테카를로법**은 환경 모델 없이 **직접 해보고 평균**을 내어 가치를 추정
  - 필요한 것은 분포 모델이 아니라 **샘플 모델**(`env.step()`)뿐
  - 대신 에피소드가 끝나야 수익을 알 수 있으므로 **일회성 과제** 전용
- 한 에피소드의 경험을 **뒤에서부터** 훑으면 거쳐 간 모든 상태의 수익을 한 번에 얻음
  - `G = γ·G + reward` — 3장의 재귀 구조를 그대로 쓴 한 줄
  - 갱신은 1장의 증분 평균 그대로: `V(s) ← V(s) + (1/n){G - V(s)}`
- 모델이 없으므로 정책 개선에는 **`V`가 아니라 `Q`가 필요**
  - `μ(s) = argmax_a Q(s,a)` — `V`로 하려면 `p`와 `r`이 필요해 쓸 수 없음
- 제어에는 두 가지 처방이 붙음
  - **ε-탐욕 정책** — 탐욕 정책만으로는 방문하지 않는 상태가 생겨 학습이 막힘
  - **고정값 α** — 정책이 계속 바뀌므로 최근 수익에 더 비중을 둠(1.5절의 비정상 문제와 같은 처방)
- **온-정책 / 오프-정책** — 행동하는 정책 `b`와 평가할 정책 `π`가 같은가 다른가
  - 오프-정책은 **중요도 샘플링**으로 데이터를 보정: `E_π[x] = E_b[x·π(x)/b(x)]`
  - 가중치 `ρ`가 걸음마다 곱해져 쌓이므로 **분산이 커짐**. `b`를 `π`에 가깝게 둘수록 완화
- 남은 문제 — MC법은 **에피소드가 끝날 때까지 아무것도 배우지 못함**
  - 판이 길면 갱신이 드물고, 끝이 없는 지속적 과제에는 아예 쓸 수 없음
- 다음 장에서는 **한 걸음마다 갱신**하는 TD법으로 이 문제를 푼다
  - DP의 '한 걸음 앞을 내다보는 갱신'과 MC의 '경험에서 배우기'를 합친 것
