# CHAPTER 4 동적 프로그래밍
- 3장에서 벨만 방정식을 얻었지만, 실제로 푸는 방법은 두 칸짜리 예제에서 손으로 세운 것뿐이었음
- 이 장에서는 그 방정식을 **컴퓨터가 반복 계산으로 푸는 방법**을 만듦 — **동적 프로그래밍**(DP)
- 두 가지 알고리즘이 목표
  - **정책 반복법**(policy iteration) — 평가와 개선을 번갈아 반복
  - **가치 반복법**(value iteration) — 둘을 하나로 합쳐 최적 가치를 직접 구함
- 전제: **환경의 모델(`p`, `r`)을 완전히 알고 있음**. 이 전제가 깨지는 것이 5장부터
## 4.1 동적 프로그래밍과 정책 평가
### 4.1.1 동적 프로그래밍 기초
- ![](../images/figures/fig%204-1.png)
  - 3.2절에서 한 일 — 환경 모델(`p`, `r`)과 정책 `π`를 벨만 방정식에 넣고 연립방정식으로 풀었음
  - **볼 곳**: 가운데 주황 상자 '연립방정식 계산기'
  - 상태가 늘면 이 상자가 `|S|×|S|` 행렬을 다뤄야 해서 무거워짐(`O(|S|³)`)
  - 이 장에서는 이 상자를 **반복 계산**으로 바꿈
- ![](../images/figures/fig%204-2.png)
  - 소재는 다시 두 칸짜리 그리드 월드, 정책은 `Left`/`Right` 각 `0.5`인 무작위 정책(`γ=0.9`)
- ![](../images/equations/e%204-1.png)
  - 풀어야 할 벨만 방정식([식 4.1]) — 3장의 [식 3.6]과 같은 식
- 핵심 아이디어: **등호를 대입으로 바꿔 읽기**
- ![](../images/equations/e%204-2.png)
  - 우변에 `V_k`를 넣어 좌변 `V_{k+1}`을 얻는 **갱신식**으로 봄([식 4.2])
  - 이 반복을 **반복적 정책 평가**(iterative policy evaluation)라고 함
  - 대문자 `V`를 쓰는 이유 — 참값 `v_π`가 아니라 **추정치**이기 때문(1장의 `q`/`Q`와 같은 약속)
- ![](../images/figures/fig%204-3.png)
  - **볼 곳**: 위에서 아래로 내려오며 `Σ`가 하나씩 사라짐
  - 1단계: `Σ_{a,s'}`를 `Σ_a Σ_{s'}`로 분리
  - 2단계: 상태 전이가 결정적(`s' = f(s,a)`)이면 `Σ_{s'}`가 통째로 사라짐
- ![](../images/equations/e%204-3.png)
  - 실제 구현에 쓰는 형태([식 4.3]) — `V_{k+1}(s) = Σ_a π(a|s){ r(s,a,s') + γ V_k(s') }`
- ![](../images/figures/fig%204-4.png)
  - `L1`의 갱신을 그린 백업 다이어그램. `V_{k+1}(L1) = 0.5{-1 + 0.9V_k(L1)} + 0.5{1 + 0.9V_k(L2)}`
- ![](../images/figures/fig%204-5.png)
  - `V_0 = (0, 0)`에서 한 번 갱신한 결과 `V_1 = (0, -0.5)`
  - **볼 곳**: `L1`이 여전히 `0`인 것 — `-1`과 `+1`이 반반이라 상쇄됨
  - `L2`는 `0.5×0 + 0.5×(-1) = -0.5`
  - 참값은 `(-2.25, -2.75)`이므로 아직 한참 멀었음. 이 갱신을 계속 반복하면 됨
- 왜 수렴하는가 — 3.2.2에서 확인했듯 매 반복 오차가 `γ`배로 줄어듦(축소 사상)
  - `γ < 1`이면 반드시 유일한 해로 수렴
### 4.1.2 반복적 정책 평가_첫 번째 구현
- 예제 코드: [`s01_dp.py`](s01_dp.py) — 배열 두 개(`V`, `new_V`)를 쓰는, 식을 가장 단순하게 옮긴 구현
```python
V = {'L1': 0.0, 'L2': 0.0}
new_V = V.copy()

cnt = 0  # 갱신 횟수 기록
while True:
    new_V['L1'] = 0.5 * (-1 + 0.9 * V['L1']) + 0.5 * (1 + 0.9 * V['L2'])
    new_V['L2'] = 0.5 * (0 + 0.9 * V['L1']) + 0.5 * (-1 + 0.9 * V['L2'])

    # 갱신된 양의 최댓값
    delta = abs(new_V['L1'] - V['L1'])
    delta = max(delta, abs(new_V['L2'] - V['L2']))
    V = new_V.copy()

    cnt += 1
    if delta < 0.0001:  # 임계값 = 0.0001
        print(V)
        print('갱신 횟수:', cnt)
        break
```
- **언제 멈추는가** — 갱신 폭 `delta`(모든 상태 중 가장 크게 변한 값)가 임계값보다 작아지면 종료
  - 참값을 모르므로 '더 이상 거의 변하지 않는다'를 수렴의 신호로 삼음
```
{'L1': -2.249167525908671, 'L2': -2.749167525908671}
갱신 횟수: 76
```
- **볼 곳**: 3.2절에서 연립방정식으로 얻은 정확해 `(-2.25, -2.75)`와 소수점 셋째 자리까지 같음
  - 남은 오차 `8.3e-4`는 임계값 `1e-4`에서 멈췄기 때문(오차 ≈ `delta × γ/(1-γ)` = `delta × 9`)
- ![](../images/figures/fig%204-6.png)
  - 이 구현의 갱신 방식 — **`V`를 읽어 `new_V`에 씀**
  - **볼 곳**: 화살표의 출발점이 항상 위쪽 `V` 배열
  - 한 번의 갱신(스윕) 동안 `V`는 고정되므로, `L1`을 갱신해도 `L2` 계산에는 옛 값이 쓰임
### 4.1.3 반복적 정책 평가_다른 구현 방법
- 배열 하나만 쓰고 **제자리에서 덮어쓰는** 방식(in-place)
- 예제 코드: [`s02_dp_inplace.py`](s02_dp_inplace.py)
```python
V = {'L1': 0.0, 'L2': 0.0}

cnt = 0
while True:
    t = 0.5 * (-1 + 0.9 * V['L1']) + 0.5 * (1 + 0.9 * V['L2'])
    delta = abs(t - V['L1'])
    V['L1'] = t          # 여기서 곧바로 덮어씀

    t = 0.5 * (0 + 0.9 * V['L1']) + 0.5 * (-1 + 0.9 * V['L2'])   # 방금 바뀐 V['L1']을 씀
    delta = max(delta, abs(t - V['L2']))
    V['L2'] = t

    cnt += 1
    if delta < 0.0001:
        print(V)
        print('갱신 횟수:', cnt)
        break
```
- ![](../images/figures/fig%204-7.png)
  - **볼 곳**: 화살표가 **같은 배열 안에서** 돌아옴. `new_V`가 없음
  - `L2`를 갱신할 때 이미 새로 계산된 `L1`을 쓰므로, 갱신된 정보가 **같은 스윕 안에서 전파**됨
```
{'L1': -2.2493782177156936, 'L2': -2.7494201578106514}
갱신 횟수: 60
```
- **볼 곳**: 갱신 횟수가 `76 → 60`으로 줄었음. 답은 같은데 **더 빨리 수렴**
  - 새 값이 곧바로 다음 계산에 반영되기 때문
  - 메모리도 배열 하나만 쓰면 되므로 이득
- 그래서 앞으로의 구현은 모두 **제자리 갱신** 방식을 씀

### 4.2.2 defaultdict 사용법
- 상태가 `(h, w)` 튜플이라 딕셔너리로 다루는 편이 자연스러움
- 다만 없는 키에 접근하면 `KeyError`가 나므로 `collections.defaultdict`를 씀
```python
from collections import defaultdict

V = defaultdict(lambda: 0)          # 없는 상태의 가치는 0
pi = defaultdict(lambda: {0: 0.25, 1: 0.25, 2: 0.25, 3: 0.25})  # 없는 상태는 무작위 정책
```
- **왜 편한가** — 모든 상태를 미리 `0`으로 채워두는 초기화 코드가 필요 없음
  - `V[(0, 0)]`처럼 처음 접근하는 순간 기본값이 만들어짐
  - 정책도 마찬가지 — 상태를 일일이 나열하지 않고도 '기본은 무작위'를 표현
- 주의할 점: `V.keys()`는 **한 번이라도 접근한 상태**만 담고 있음
  - 그래서 `policy_eval()`은 `env.states()`로 전체를 한 번 훑은 뒤에 `V.keys()`를 씀
### 4.2.3 반복적 정책 평가 구현
- ![](../images/figures/fig%204-12.png)
  - 한 번의 **스윕**(sweep)에서 상태를 훑는 순서 — 왼쪽 위에서 오른쪽으로, 줄이 끝나면 다음 줄
  - **볼 곳**: 실선(오른쪽으로 이동)과 점선(줄바꿈). `env.states()`가 내놓는 순서 그대로
  - 이 순서가 in-place 갱신의 전파 방향을 정함 — 목표가 오른쪽 위에 있으므로
    정보가 되돌아오는 데 여러 스윕이 필요
- 예제 코드: [`s04_policy_eval.py`](s04_policy_eval.py)
```python
def eval_onestep(pi, V, env, gamma=0.9):
    for state in env.states():        # 각 상태에 접근
        if state == env.goal_state:   # 목표 상태에서의 가치 함수는 항상 0
            V[state] = 0
            continue

        action_probs = pi[state]
        new_V = 0
        for action, action_prob in action_probs.items():
            next_state = env.next_state(state, action)
            r = env.reward(state, action, next_state)
            new_V += action_prob * (r + gamma * V[next_state])   # [식 4.3]
        V[state] = new_V              # 제자리 갱신
    return V


def policy_eval(pi, V, env, gamma, threshold=0.001):
    while True:
        old_V = V.copy()
        V = eval_onestep(pi, V, env, gamma)
        delta = max(abs(V[s] - old_V[s]) for s in V.keys())
        if delta < threshold:
            break
    return V
```
- `eval_onestep()`이 **한 번의 스윕**(모든 상태를 한 번씩 갱신), `policy_eval()`이 그 반복
- **목표 상태를 `0`으로 고정하는 이유**
  - 목표는 종료 상태라 그 뒤로 받을 보상이 없음 → `v(goal) = 0`
  - 이 처리를 빼먹으면 목표에서 다시 출발하는 것처럼 계산되어 값이 발산함
- 3×4 그리드 월드에서 무작위 정책을 평가한 결과(임계값 `0.001`, 23회 스윕)
  ```
     0.03    0.10    0.21    0.00
    -0.03   -0.14   -0.50   -0.37
    -0.10   -0.22   -0.43   -0.78
  ```
- ![](../images/figures/fig%204-13.png)
  - 같은 결과를 `render_v()`로 그린 것. 각 칸의 화살표 네 개가 무작위 정책을 나타냄
  - **볼 곳**: 목표 왼쪽 칸(`0.21`)만 초록이고, **오른쪽 아래로 갈수록 빨강이 짙어짐**
  - 오른쪽 아래(`-0.78`)가 가장 나쁨 — 폭탄 바로 아래라 무작위로 걸으면 폭탄에 닿기 쉬움
  - 왼쪽 아래(`-0.10`)는 폭탄에서 멀어 상대적으로 덜 나쁨
  - 이 값들은 **무작위로 걸었을 때**의 성적 — 좋은 정책을 찾으면 전부 양수가 됨(4.4절)
  - 3장 [`ch03/s01_bellman_linear.py`](../ch03/s01_bellman_linear.py)가 연립방정식으로 구한 정확해와
    소수점 아래 9자리까지 일치함(임계값을 `1e-10`으로 낮췄을 때)
## 4.3 정책 반복법
### 4.3.1 정책 개선
- 지금까지는 **주어진 정책을 평가**하기만 했음. 이제 정책을 **더 좋게 만드는** 단계를 붙임
- ![](../images/equations/e%204-4%20&%204-5.png)
  - 3.5.2에서 본 식 — 최적 가치 `v*`를 알면 최적 정책은 탐욕적으로 뽑힘([식 4.4], [식 4.5])
  - 하지만 우리는 아직 `v*`를 모름. 대신 **지금 정책의 가치 `v_μ`는 알고 있음**(4.2.3에서 구함)
- ![](../images/equations/e%204-6%20&%204-7.png)
  - `v*` 자리에 `v_μ`를 넣어 탐욕화한 새 정책 `μ'`([식 4.6], [식 4.7])
  - `μ'(s) = argmax_a Σ_{s'} p(s'|s,a){ r(s,a,s') + γ v_μ(s') }`
- ![](../images/equations/e%204-8.png)
  - 상태 전이가 결정적일 때의 형태([식 4.8])
- 이렇게 만든 `μ'`는 **반드시 `μ` 이상**임이 보장됨(정책 개선 정리)
  - 직관: 각 상태에서 '한 걸음만 더 좋게' 골랐고, 그 뒤는 여전히 `μ`를 따르니 손해 볼 일이 없음
  - 게다가 그 한 걸음의 이득이 다음 평가에서 전체로 퍼짐
- 3장 [`ch03/s03_q_function.py`](../ch03/s03_q_function.py)에서 이미 한 번 해봤음 —
  무작위 정책의 `Q`를 탐욕화하자 폭탄을 피하는 정책이 나왔던 그 계산이 [식 4.6]
### 4.3.2 평가와 개선 반복
- 한 번 개선해서 얻은 `μ'`도 최적은 아님 → **다시 평가하고 다시 개선**
- ![](../images/figures/fig%204-14.png)
  - **볼 곳**: 파란 화살표(평가)와 주황 화살표(탐욕화)가 **번갈아 이어지며 내려감**
  - `π_0 → V_0 → μ_1 → V_1 → μ_2 → ... → μ* → V*`
  - 정책은 매번 나빠지지 않고(`μ_1 ≤ μ_2 ≤ ...`), 결정적 정책의 수는 유한하므로
    **언젠가 반드시 멈춤** — 멈춘 곳이 최적 정책
- 멈추는 조건: 탐욕화해도 **정책이 바뀌지 않을 때**
  - 그때는 `μ = greedy(v_μ)`이므로 벨만 최적 방정식이 성립 → `v_μ = v*`
- 이 절차를 **정책 반복법**(policy iteration)이라고 함
## 4.4 정책 반복법 구현
- ![](../images/figures/fig%204-15.png)
  - 대상은 그대로 3×4 그리드 월드
### 4.4.1 정책 개선
- 예제 코드: [`s05_policy_iter.py`](s05_policy_iter.py)의 `greedy_policy()`
```python
def greedy_policy(V, env, gamma):
    pi = {}
    for state in env.states():
        action_values = {}
        for action in env.actions():
            next_state = env.next_state(state, action)
            r = env.reward(state, action, next_state)
            action_values[action] = r + gamma * V[next_state]   # [식 4.8]

        max_action = argmax(action_values)
        action_probs = {0: 0, 1: 0, 2: 0, 3: 0}
        action_probs[max_action] = 1.0    # 고른 행동에만 확률 1
        pi[state] = action_probs
    return pi
```
- 결과는 **결정적 정책**이지만 형식은 그대로 `{행동: 확률}` — 평가 코드를 고치지 않고 쓰기 위함
- `argmax(d)`를 직접 만든 이유 — 값이 같은 행동이 여럿일 때 **어느 것을 고를지 정해두기 위해**
  - 이 구현은 마지막에 나온 키를 고름. 그래야 실행할 때마다 정책이 흔들리지 않음
### 4.4.2 평가와 개선 반복
```python
def policy_iter(env, gamma, threshold=0.001, is_render=True):
    pi = defaultdict(lambda: {0: 0.25, 1: 0.25, 2: 0.25, 3: 0.25})
    V = defaultdict(lambda: 0)

    while True:
        V = policy_eval(pi, V, env, gamma, threshold)  # 평가
        new_pi = greedy_policy(V, env, gamma)          # 개선

        if new_pi == pi:   # 정책이 더 이상 바뀌지 않으면 종료
            break
        pi = new_pi
    return pi
```
- 그림 4-14를 그대로 옮긴 여덟 줄. `V`를 매번 새로 만들지 않고 **이어서 씀**에 주의
  - 이전 정책의 가치에서 출발하므로 두 번째 평가부터는 훨씬 빨리 수렴
- 실행 결과 — 평가·개선 사이클 **5회** 만에 정책이 고정됨
  ```
  최적 가치 함수
       0.81    0.90    1.00    0.00
       0.73    0.81    0.90    1.00
       0.66    0.73    0.81    0.73
  최적 정책
     RIGHT  RIGHT  RIGHT   GOAL
        UP   WALL     UP     UP
     RIGHT  RIGHT     UP   LEFT
  ```
  - 가운데 줄 두 번째 값 `0.81`은 **벽 자리**(`(1,1)`)임에 주의
    - `env.states()`가 벽도 내놓으므로 계산은 되지만, 갈 수 없는 칸이라 의미가 없음
    - `render_v()`가 그 칸을 회색으로 칠하고 값을 표시하지 않는 이유
- ![](../images/figures/fig%204-16.png)
  - **왼쪽(처음)**: 그림 4-13과 같은 무작위 정책의 가치 — 온통 빨강, 화살표는 사방
  - **오른쪽(마지막, 네 번째 갱신)**: 전부 초록, 화살표가 **하나씩만** 남음
  - **볼 곳**: 색이 통째로 뒤집혔다는 것. 같은 환경인데 정책만 바꿔 `-0.78`이 `0.73`이 됨
  - 값 읽는 법: 목표 왼쪽 칸이 `1.00`(한 걸음이면 `+1`), 그 왼쪽이 `0.90`(= `γ×1.00`),
    그 왼쪽이 `0.81`(= `γ²`) — **목표까지의 걸음 수만큼 `γ`가 곱해짐**
  - 오른쪽 아래 `0.73`은 `γ³` — 폭탄을 피해 왼쪽으로 돌아가므로 세 걸음
  - 폭탄 칸 바로 왼쪽(`0.90`)에서 화살표가 **위**를 향함. 오른쪽으로 가면 `-1`이라 돌아가는 편이 나음
  - 폭탄 오른쪽 아래 칸의 화살표가 **왼쪽**인 것도 같은 이유
- 가치 함수가 고르게 짙은 초록인 이유는 최적 정책에서는 **어느 칸에서 출발해도 사과에 닿기 때문**
## 4.5 가치 반복법
### 4.5.1 가치 반복법 도출
- ![](../images/figures/fig%204-17.png)
  - 정책 반복법의 구조 — `μ`와 `V` 사이를 평가(파랑)와 개선(주황)이 오감
- ![](../images/figures/fig%204-18.png)
  - **볼 곳**: 파란 화살표가 매번 위쪽 선(`V = v_μ`)에 **정확히 닿음**
  - 즉 평가를 **수렴할 때까지 끝까지** 돌린다는 뜻. 그런데 그럴 필요가 있을까?
- ![](../images/figures/fig%204-19.png)
  - **볼 곳**: 이번에는 파란 화살표가 선에 닿기 전에 **중간에서 꺾임** — 평가를 도중에 끊음
  - 그래도 두 선이 만나는 꼭짓점(`v*, μ*`)으로 수렴함
  - 화살표 하나하나는 짧아졌지만 개수가 늘어 결국 같은 곳에 도착 — 오히려 전체 계산은 줄어듦
- 극단적으로 **평가를 단 한 번의 스윕만** 하면 어떻게 될까?
- ![](../images/figures/fig%204-20.png)
  - 지금까지의 정책 반복법 — 파란 격자(평가)를 `n`번 반복한 뒤에야 주황 격자(개선)로 넘어감
- ![](../images/figures/fig%204-21.png)
  - **볼 곳**: 개선(주황)과 평가(파랑)가 **한 칸 단위로** 번갈아 일어남
  - 한 상태를 개선하고 곧바로 그 상태를 평가하고, 다음 상태로 넘어감
- ![](../images/equations/e%204-9.png)
  - 평가 한 스윕의 갱신식([식 4.9]) — 4.1절의 [식 4.2]와 같은 식
- ![](../images/equations/e%204-10.png)
  - 그런데 개선 단계에서 나온 정책은 **결정적**(`a = μ(s)`)이므로 `Σ_a π(a|s)`가 사라짐([식 4.10])
  - **볼 곳**: 이제 평가 쪽 식이 `Σ_{s'} p(s'|s,a){ r(s,a,s') + γV(s') }` 하나만 남았음
- ![](../images/figures/fig%204-22.png)
  - 두 단계에서 실제로 하는 계산을 나란히 쓴 것([식 4.8]과 [식 4.10])
  - **볼 곳**: 하늘색으로 칠해진 부분이 **완전히 같은 식**(오른쪽 아래 '같은 계산')
  - 개선은 그 값들의 `argmax`(어떤 행동인지), 평가는 고른 행동의 그 값(얼마인지)을 씀
  - 그렇다면 굳이 두 번 계산할 이유가 없음 → **`max`로 한 번에**
- ![](../images/equations/e%204-11.png)
  - 두 단계를 합친 갱신식([식 4.11]) — `V'(s) = max_a Σ_{s'} p(s'|s,a){ r(s,a,s') + γV(s') }`
  - 3장 벨만 최적 방정식([식 3.16])과 같은 모양. **정책이 등장하지 않음**
- ![](../images/figures/fig%204-23.png)
  - 상태 전이가 결정적일 때의 형태([식 4.13]) — `V'(s) = max_a { r(s,a,s') + γV(s') }`
- 이 갱신을 반복하는 것이 **가치 반복법**(value iteration)
  - 정책 평가([식 4.3])와 비교하면 **`Σ_a π(a|s)` 자리가 `max_a`로 바뀐 것뿐**
  - 정책을 따로 유지하지 않으므로 코드가 더 짧아짐
### 4.5.2 가치 반복법 구현
- 예제 코드: [`s06_value_iter.py`](s06_value_iter.py)
```python
def value_iter_onestep(V, env, gamma):
    for state in env.states():
        if state == env.goal_state:
            V[state] = 0
            continue

        action_values = []
        for action in env.actions():
            next_state = env.next_state(state, action)
            r = env.reward(state, action, next_state)
            action_values.append(r + gamma * V[next_state])   # [식 4.13]

        V[state] = max(action_values)   # 정책 평가와 다른 곳은 여기뿐
    return V
```
- `eval_onestep()`과 나란히 놓고 보면 차이가 분명함
  |  |정책 평가 |가치 반복법 |
  |:--|:--|:--|
  |행동을 다루는 법 |`Σ_a π(a\|s) × (...)` |`max_a (...)` |
  |필요한 것 |정책 `π` |없음 |
  |수렴하는 값 |`v_π` |`v*` |
- 최적 가치를 얻은 뒤 마지막에 한 번만 탐욕화해 정책을 뽑음
- ![](../images/equations/e%204-12.png)
  - `μ*(s) = argmax_a Σ_{s'} p(s'|s,a){ r(s,a,s') + γV*(s') }`([식 4.12])
  - 코드에서는 4.4.1의 `greedy_policy()`를 그대로 재사용
```python
V = value_iter(V, env, gamma)       # 최적 가치 함수 찾기
pi = greedy_policy(V, env, gamma)   # 최적 정책 찾기
```

  ```
       0.81    0.90    1.00    0.00
       0.73    0.81    0.90    1.00
       0.66    0.73    0.81    0.73
  ```
- ![](../images/figures/fig%204-24.png)
  - **왼쪽(처음)**: 전부 `0.00`. 아무 정보도 없는 상태에서 출발
  - **오른쪽(마지막, 세 번째 갱신)**: 정책 반복법의 답과 **완전히 같은 값**
  - **볼 곳**: 왼쪽에서 오른쪽으로 가는 데 갱신이 세 번밖에 걸리지 않았다는 것
  - 정책 반복법은 사이클마다 평가를 여러 스윕 돌렸지만, 가치 반복법은 스윕 4번이 전부
- ![](../images/figures/fig%204-35.png)

  |  |정책 반복법 |가치 반복법 |
  |:--|:--|:--|
  |구조 |평가(여러 스윕) ↔ 개선 |한 종류의 스윕만 반복 |
  |중간 산출물 |매 사이클의 정책 `μ_k` |없음(마지막에 한 번 뽑음) |
  |이 예제에서 |사이클 5회(내부 평가 포함) |스윕 4회 |
  |장점 |정책이 빨리 좋아지는 편 |구현이 단순하고 계산이 가벼움 |
  - 둘은 '평가를 얼마나 끝까지 돌리는가'라는 **같은 축의 양 끝**일 뿐, 본질은 같음
    (그 사이를 **일반화된 정책 반복**(GPI)이라고 부름 — 5장 이후 알고리즘도 모두 이 틀 안에 있음)
## 4.6 정리
- **동적 프로그래밍**은 벨만 방정식의 등호를 **갱신식으로 바꿔 반복**하는 방법
  - `V_{k+1}(s) = Σ_a π(a|s){ r(s,a,s') + γV_k(s') }` — 오차가 매 스윕 `γ`배로 줄어 수렴
  - 배열 하나만 쓰는 **제자리 갱신**이 더 빠름(76회 → 60회)
- **반복적 정책 평가** — 주어진 정책 `π`의 가치 `v_π`를 구함([`s04_policy_eval.py`](s04_policy_eval.py))
  - 목표 상태의 가치는 `0`으로 고정할 것
- **정책 반복법** — 평가와 **탐욕화**(개선)를 번갈아 반복([`s05_policy_iter.py`](s05_policy_iter.py))
  - `μ'(s) = argmax_a { r(s,a,s') + γ v_μ(s') }` — 새 정책은 반드시 이전 이상
  - 정책이 바뀌지 않으면 종료. 그때가 최적
- **가치 반복법** — 평가를 한 스윕으로 줄이고 개선과 합친 것([`s06_value_iter.py`](s06_value_iter.py))
  - `V'(s) = max_a { r(s,a,s') + γV(s') }` — 정책 평가의 `Σ_a π` 자리를 `max_a`로
  - 정책 없이 최적 가치를 직접 구하고, 마지막에 한 번 탐욕화
- 3×4 그리드 월드에서 두 방법 모두 같은 최적 가치·최적 정책에 도달
  - 목표에서 멀어질수록 값이 `γ`배씩 깎임(`1.00 → 0.90 → 0.81 → 0.73`)
- **한계**: 이 장의 모든 방법은 **환경 모델 `p`와 `r`을 완전히 알고 있어야** 함
  - `next_state()`와 `reward()`를 직접 호출하고 있다는 점에 주목
  - 현실 문제에서는 모델을 모르는 경우가 대부분이고, 상태 수도 감당이 안 됨
- 다음 장에서는 모델 없이 **직접 경험해 얻은 표본**으로 가치를 추정함 → 몬테카를로법
